# Suite navigation: study an interface, not one screenshot

Read when researching expanded marketing navigation. Find the actual trigger, positioning root, clipping wrapper, backdrop, scrolling element and focus boundary. Panels may be portalled outside the header. Header-only selectors can miss a visible mega-menu; positive rectangles and opacity do not prove a translated/clipped descendant is visible.

Distinguish buttons, anchors, labels/checked inputs, hover/focus-within and application state. Check semantics before pressing Enter: an assumed disclosure might navigate. Record actual focus and URL. Fresh contexts separate keyboard behaviour from hover; qualify macOS/WebKit traversal conventions.

## Evidence matrix

- Rest → opening → settled panel → another category of different height → closing. Record elapsed samples and playable captures, not filename delays as timings.
- Near/far diagonal travel, pointer coordinates and whether the path crosses another trigger. Test brief crossings, leaving/re-entering and rapid reversal.
- Tab/Shift+Tab, actual activation, first child, focus exit, Escape, return focus and stale-hover reopening. Failed locators are not site defects.
- Phone root → category → scrolling → Back → root → Close. Test Escape independently; do not try Back after Escape already closed everything. Ensure account actions cannot cover the last link.
- Both sides of the actual breakpoint, short height, resize while open, coarse pointer and initial/live reduced motion. Name untested combinations. Unsupported mobile WebKit wheel calls are harness limits, not touch-scroll defects.

Open cited captures. Retain diagnostic attempts with corrected follow-ups; curate rather than endorse every generated image.

## Code association and materials

Collect duration, delay and easing separately for shell, content, backdrop, chevron and media. Trace category identity, height measurement, cancellation, focus ownership, scroll locking and cleanup. Associate imported helpers with their implementation before claiming safe-polygon or hover-intent behaviour. An Escape handler elsewhere in a bundle is not evidence about the menu.

For CSS panels inspect pointer-corridor pseudo-elements, translated-but-focusable links, checked relationships, breakpoints, discrete display transitions and overflow. For application panels inspect portals, state attributes, measured-height handoff and overlapping entering/exiting layers. Do not assume the user's project has the same library or copy delivered code.

Measure header/panel alignment, column measures, secondary rail, type/description hierarchy, edges, corners, elevation, imagery and footer. Explain why the architecture suits the information; do not imitate product count to fill space.

## Transfer

Deliver an original state model, destination map, material roles, choreography, phone alternative and acceptance list. Separate verified mechanics from proposed values. Carry each defining finding into a direction decision and later an implemented state plus a viewed capture. Mark suite navigation unimplemented if the candidate remains a section-anchor list.

Dated calibration: Stripe's 2026-10-11 specimen used a portalled shared popup, clip reveal, measured-height category changes and separate background/backdrop layers. Shopify used hover/focus-within translated desktop panels and checkbox-controlled phone levels. Their semantics and dismissal/reduced-motion behaviour differed; neither is a universal accessibility template. Refresh values in the dated dossier, not as permanent tokens here.
