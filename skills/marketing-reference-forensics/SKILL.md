# Marketing Reference Forensics

For expanded marketing navigation, also read [navigation forensics](references/navigation-forensics.md): category switching, layered timing, focus and phone drill-down need evidence beyond an open screenshot.

Produce knowledge another designer-engineer can use, not a moodboard. Preserve the user's selected direction and phase boundary. Research does not authorize implementation, publication, signup, prompt submission, or reuse of proprietary assets.

Read [the inspection protocol](references/inspection-protocol.md) and [material forensics](references/material-forensics.md) before collecting evidence, and [the evidence model](references/evidence-model.md) before conclusions. Material forensics is required for visual-reference work, not an optional polish pass.

When implementation mechanics are in scope, read [code investigation](references/code-investigation.md) to trace visible elements to public CSS, state and runtime behaviour.

For each site establish the visitor question, the page's argument, the visual mechanism carrying it, and public implementation evidence. Inspect actual rendered states: source text alone is insufficient.

Separate **observed**, **measured**, **public code**, **inference**, and **proposed implementation**. A library string in a bundle is not proof it animates the inspected scene. A screenshot is not proof of interaction. Do not claim access to private source.

Capture readable sections, mobile recompositions, navigation states and sampled motion. Open selected captures before citing them. Full-page images are for rhythm, not authoritative proof of sticky or scroll-driven content.

Finish with illustrated per-site notes, a role-based material map, concrete recipes, transferable versus non-transferable decisions, an evidence index and coverage limits. A narrative analysis without actual colour, type, edge, corner, surface and media-treatment evidence is incomplete. Every material conclusion needs a URL/date/viewport/state/capture. No arbitrary iteration cap overrides the user's requested thoroughness.
