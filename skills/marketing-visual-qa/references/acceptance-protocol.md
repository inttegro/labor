# Visual acceptance

## Compare equivalent evidence

Match viewport, zoom, crop and section job. Hero to hero, connected demo to connected demo, suite discovery to suite discovery. A concept's missing proof chapter is not the same kind of gap as bad typography.

Open actual images. Full-page thumbnails show rhythm; viewport captures show craft. A pixel diff proves change, not quality. Validate sticky/lazy captures before interpretation.

## Purpose

Can a newcomer identify category, audience, value, suite breadth and next step? Does media misclassify the company? Can the visitor explain why products connect? Is there a primary route and useful secondary evaluation path? Are claims qualified?

After hero/first explanation, paraphrase what a stranger would think the business sells. If too narrow, prettier buttons won't fix it.

## Composition and type

Check focal hierarchy, media/text balance, alignment, gutters, measures/breaks, optical baselines, section rhythm and variation. Inspect font loading and axes. Look for arbitrary labels, numbered chrome, decorative italics, identical cards or purposeless gaps. Don't ban those forms; explain the particular mismatch.

## Media

At rendered size check crop, legibility, edges, lighting, authentic UI, data continuity and adjacent-claim support. Check mobile art direction, poster, loading, blocked media, pause and reduced motion. A first frame cannot validate a sequence.

## Interaction

Test pointer, keyboard, touch layout, focus, Enter/Space, Escape, dismissal, focus return, tabs/accordions and rapid reversal. Content remains associated with labels. Test sticky-header obstruction and short heights. Don't submit real forms or perform external actions without authority.

## Technical floor

Use narrow/ordinary phone, intermediate and wide desktop, plus short height for sticky stories. Inspect zoom/reflow, long copy, overflow, blank reveal states and missing media. Test intended engines; disclose one-engine limits.

Console/network, semantic checks and performance measurements support but don't replace visual inspection. Local screenshots don't establish field Core Web Vitals or conversion.

## Ledger and gates

Record reference capture, candidate capture, mismatch, impact, proposed fix, implemented revision, after-capture and status. Separate strategy/composition/execution.

Observable gates:
- Meaningful amount/status readable at390px without zoom.
- Scene changes preserve identity and predictable focus.
- Developer route visible without unverified availability.
- Blocked video leaves proposition/action understandable.

Avoid “looks premium” or “95% like Linear.”

Research complete means usable evidence, guidance and viewed captures. Direction ready means coherent language and representative media/contracts. Implementation ready requires resolved authority/claims. Launch ready separately requires destinations, approved claims, accessibility, performance, browser coverage and deployment evidence.

Never automatically cross phases. Calibrate against live reference study and applicable interface guidance such as the [Vercel Web Interface Guidelines](https://github.com/vercel-labs/web-interface-guidelines). Apply critically; not every tab needs URL state and not every transform is cheap.
