# Material acceptance: inspect the experience, not the token list

The goal is not identical pixels to a reference. The candidate should show comparable intentionality in its own material language, at the same display size and comparable section job.

## Required comparison

Open candidate and reference full-view captures, then inspect a native-scale detail containing type, a media edge, an inner product element and a control. Use both desktop and phone. Do not compare a zoomed reference artwork with a tiny full-page candidate. Record the state and ensure consent, loading or lazy content has not distorted the specimen.

Evaluate each independently:

| Gate | Questions that must have concrete answers |
| --- | --- |
| Colour hierarchy | What is the canvas, field, object and focal accent? Can the reader distinguish atmosphere from status? Does the most saturated area support the proposition? Are required text and controls accessible on their actual composites? |
| Edges | Can each repeated boundary be explained? Are product, page and control edges differentiated? Are pseudo-rings/shadows counted? If lines are the strongest repeated feature, is that intentional and supported by content? |
| Corners | Do chapter, media, product and action shapes form a coherent role hierarchy? Are nested radii optically aligned? Has a universal radius been added to artwork that should remain square? |
| Surfaces and light | Is depth tied to a focal object? Are shadows, glass, gradient and grain consistent with a lighting model? Does a flat screenshot sit awkwardly inside excessive mock-device chrome? |
| Type | Are actual loaded files/axes correct? Are headings shaped through measure, weight and tracking, not arbitrary manual breaks? Does product UI have credible density rather than marketing display text? |
| Media format | Did the agent choose a specific gallery/still/loop/film/sequence for a reason? Is there variation in scale and density? Is the first frame useful? Are phone crops actually authored? |

## Rejection conditions

Return **needs refinement** when a representative chapter still has any major unresolved mismatch:

- Repeated equal cards and similar outlines substitute for the reference's differentiated product scenes, artwork or chapter fields.
- Multiple enclosing borders perform the same job; there is no edge ledger or justified hierarchy.
- Material rules exist in prose but the rendered work visibly uses another system.
- Decorative backgrounds dominate incomplete or implausible product evidence.
- Font fallback, unsupported weight ranges, text clipping or unreadable product detail changes the intended character.
- Motion is the only explanation, the no-motion state is empty, or a scroll effect obstructs normal reading.

These are contextual tests, not bans on cards, borders, small radii, serif, gradients or animation. Stripe's quiet structured edges and Linear's lit product seams are counterexamples to blanket rules. A card count or similarity percentage is not an acceptance metric.

## Report actionable findings

For each: reference image/state → candidate image/state → observed material difference → visitor effect → exact proposed change → replacement mechanism → check after change. Include selector/source when available. “Remove border” is incomplete if it destroys grouping; say whether spacing, background, crop or product hierarchy will replace it.

Maintain four separate outcomes: strategy, composition, materials, media/interaction. A research deliverable may pass evidence review while a prototype still fails material execution. A visual pass is not a conversion result, accessibility certification or production-readiness claim.

## Verify skill behaviour too

When refining this workflow, exercise it on raw artifacts with a realistic brief and no pre-written conclusions. Check whether the evaluator identifies role-specific materials, makes a presentation decision, respects the selected identity and phase, and avoids unsupported certainty. A schema validator only checks packaging; it does not establish taste or expertise.
