# Marketing Visual QA

For suite navigation, read [navigation acceptance](references/navigation-acceptance.md). A closed header cannot pass for its expanded, switching, focused and phone states.

A passing build is not a passing design. Read [the acceptance protocol](references/acceptance-protocol.md), [material acceptance](references/material-acceptance.md), the approved brief and the actual page, then compare references visually.

Evaluate proposition, composition, material execution and media truth as separate gates. Material choices are not “details” deferred until the end. Start with the largest meaningful mismatch within those gates; strength in one does not excuse failure in another. Preserve the selected direction. Don't invent a percentage for subjective confidence.

Each material finding needs capture/state, source location if available, visitor impact and concrete action. Use Before / Proposed refinement / Why for UI code reviews. Distinguish recommendation from implemented and visually verified fix.

When changes are authorized, capture before, make bounded changes, inspect after at affected sizes/states and check regressions. Continue to agreed acceptance; no arbitrary two-pass limit.

End accepted for the stated phase, needs refinement, or blocked by a specific decision. Direction acceptance isn't launch readiness; local tests aren't production proof; appearance isn't measured conversion.
